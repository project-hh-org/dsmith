## 해석 한계

**이번 보고서에서 다룬 것**
- 반복 3회: 프롬프트·조건별 평균과 최소–최대를 `## 반복 통계`에 싣고, `## 대응 비교`에서 프롬프트 12개를 단위로 부호 검정(양쪽 정확 p)과 평균 차이의 95% 부트스트랩 CI(시드 고정)를 낸다. 에이전트 출력의 실행 간 변동은 반복 범위 안에서만 본 것이다.
- 표본 단위는 프롬프트다. 프롬프트 수가 작아(N=12) 검정력이 낮고, 프롬프트는 이 하네스에 들어 있는 UI 생성 요청이라 "일반 UI 생성"으로 확장하지 못한다.
- 채점 독립성: dsmith 엔진과 코드를 공유하지 않는 별도 채점기가 같은 산출물을 다시 셌고(`## 독립 채점`), dsmith 점수와의 방향 일치도를 `### 일치도`에 밝혔다. 다만 독립 채점기도 같은 저자가 쓴 정규식·AST 휴리스틱이라 완전한 제3자 평가는 아니고, 베이스의 토큰·프리셋 정의는 같은 것을 읽고, DS 모듈 목록도 dsmith 스냅샷(`ds.modules`)에서 받는다.
- 타입 검사: 바뀐 파일을 TypeScript 컴파일러로 검사했다(위 "타입 검사" 문단에 방식과 못 잡는 것을 적었다). 토큰 정의 확인은 정의 없는 var 참조 수(`undefinedVars`)로 한다.

**남은 한계**
- 렌더링하지 않았다. 화면에서 어떻게 보이는지(색 대비·레이아웃 깨짐)와 `tokens.css`가 실제로 로드되는지는 측정 밖이다 — 정의된 var 참조는 "CSS 어딘가에 선언돼 있다"까지만 확인한다.
- 타입 검사는 의존성 타입 없이 했다(복사본에 node_modules 없음). react 등 외부 패키지 API 사용과 JSX 내장 요소 속성의 타입 오류는 검사 밖이다.
- 모델 하나·에이전트 하나(관측 모델: claude-sonnet-5-5), 레포 하나(legacy-demo)다. 다른 모델·에이전트·코드베이스로 일반화하지 못한다.
- 조건 구성: 각 조건은 사용자가 칠 install 명령 그대로 만들었다 — agents-only = `install`(기본: AGENTS.md DS 섹션만, MCP·슬래시 명령 언급 없음), agents-mcp = `install --mcp`, mcp-only = `install --mcp` 뒤 AGENTS.md 섹션 삭제, dsmith = `install --mcp --skills`. AGENTS.md 섹션 문구는 설치된 표면에 따라 다르므로 조건 사이 차이에는 문구 차이가 함께 들어 있다(실제 사용자가 받는 차이와 같다). 에이전트 명령은 모든 조건이 같다(`--allowedTools mcp__dsmith` 포함).
- 대응 비교에서 쌍 3개 × 지표 4개(토큰 사용률·DS 외 컴포넌트·DS 컴포넌트 사용·독립 사용률)를 각각 검정했고 다중 비교 보정은 하지 않았다. 참고로 Bonferroni(×12)를 적용하면 토큰 사용률의 부호 검정 p는 agents-only − baseline p=0.0059, dsmith − baseline p=0.0059, dsmith − agents-only p=0.8438다.
- 95% CI는 프롬프트 12개의 백분위 부트스트랩이라 표본이 작으면 실제 포함 확률이 95%보다 낮을 수 있다. 그래서 같은 차이의 t 구간을 `## 대응 비교`에 함께 적었다(정규 근사를 가정한 비교용 값).
- 토큰 사용률이 dsmith 쪽에서 agents-only보다 오히려 낮아진 프롬프트: `01-form`(100.0% → 92.3%, dsmith DS 컴포넌트 사용 평균 2.0), `05-table`(100.0% → 98.0%, dsmith DS 컴포넌트 사용 평균 0.0), `07-tabs`(100.0% → 93.8%, dsmith DS 컴포넌트 사용 평균 0.7), `09-sidebar`(100.0% → 94.1%, dsmith DS 컴포넌트 사용 평균 1.0), `10-settings`(100.0% → 98.1%, dsmith DS 컴포넌트 사용 평균 1.0), `11-empty`(77.6% → 50.0%, dsmith DS 컴포넌트 사용 평균 1.0), `12-pagination`(94.4% → 33.3%, dsmith DS 컴포넌트 사용 평균 3.0). 사용률은 직접 쓴 스타일 값 중 토큰 참조의 비율이라, DS 컴포넌트로 조립하고 레이아웃용 기본 스케일 클래스만 몇 개 직접 쓰면 분자가 0이 돼 0%가 된다. 이는 지표의 한계이며 이런 프롬프트의 DS 활용은 `DS 컴포넌트 사용` 행에서 따로 본다.
- 준수율 분모에서 Tailwind 기본 스케일 클래스는 뺐다(별도 행).
- 변수·상수에 담은 className은 dynamic으로만 세며 준수율 분모에 들어가지 않음.
