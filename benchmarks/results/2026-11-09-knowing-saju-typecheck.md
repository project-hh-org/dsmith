# 비공개 Expo 앱 — 의존성 타입으로 다시 한 타입 검사 (2026-11-09)

[2026-11-08 실측](2026-11-08-knowing-saju-k3.md)의 산출물 72개(조건 2 × 프롬프트 12 × 반복 3)를 그대로 다시 검사했다. 에이전트는 다시 부르지 않았다. 수치만 남긴 리댁션본이다.

## 방법

- 앱 복사본에 `npm install --ignore-scripts --legacy-peer-deps`로 의존성을 설치했다(복사본에 잠금 파일이 없어 `package.json` 범위의 최신 버전이 설치됨). 설치한 복사본은 `tsc --noEmit` 오류 0이었다.
- 실행마다 에이전트가 바꾼 파일을 그 복사본 위에 덮어 얹고, 하네스와 같은 검사기(`benchmarks/src/independent/typecheck.ts`의 `typeCheckChanged`)로 바뀐 파일만 검사했다. `node_modules/react`가 풀려 모드는 "타입 검사"(아무 진단도 가리지 않음)다.

## 결과

| 지표 | baseline | agents-only |
| --- | --- | --- |
| 실행 | 36 | 36 |
| 타입 오류(의존성 없이, 11-08 보고서) | 60 | 47 |
| 타입 오류(의존성 설치 후) | 2 | 3 |
| 오류 없는 실행 | 34 | 33 |
| 오류 코드 | TS2551 × 2 | TS2551 × 3 |

다섯 건 모두 한 프롬프트(`02-confirm-sheet`)에서 `StyleSheet.absoluteFillObject`를 쓴 같은 오류다. 설치된 최신 React Native 타입에는 이 속성이 없고 `absoluteFill`만 있다. 디자인시스템 토큰·컴포넌트와는 관계없는 RN API 사용 문제이고 두 조건에서 비슷하게 나왔다(3회 중 2회 · 3회).

## 해석

- 11-08 보고서의 60 · 47은 외부 패키지 타입 없이 검사해서 생긴 진단이다. 품질 차이가 아니었다.
- 기본 설치(AGENTS.md DS 섹션)는 이 앱에서 타입 오류를 늘리지 않았다. 차이 1건은 한 프롬프트의 반복 1회분이라 차이로 읽지 않는다.
- 잠금 파일이 아닌 최신 범위 버전으로 검사했으므로, 앱이 실제로 고정한 RN 버전에서는 `absoluteFillObject`가 오류가 아닐 수 있다.
